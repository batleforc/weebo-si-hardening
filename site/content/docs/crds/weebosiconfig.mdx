- **Short names:** none

`spec` of the `WeeboSiConfig` CRD.

## Example

```yaml
apiVersion: hardening.weebo.io/v1alpha1
kind: WeeboSiConfig
metadata:
  name: my-config
spec:
  features:
    dwocPin:
      mode: DryRun
      catalog:
        - key: baseline
          name: weebo-hardened-config
          namespace: eclipse-che
      default: baseline
```

### `spec.features.endpointAuth.gateway` [#spec.features.endpointAuth.gateway]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `allowedMiddlewares` | `string[]` | no | `[]` | Traefik only: middleware names an `Ingress` may carry **after** ours. |
| `clusterDomain` | `string` | no | `"cluster.local"` | The cluster's DNS domain, which the gateway's in-cluster URL is qualified with.<br /><br />Qualified rather than left to the search path because not every router resolves through it: a proxy with its own resolver applies no search domains, so `<name>.<ns>.svc` is `Host not found` and every gated request a `500`. |
| [`custom`](#spec.features.endpointAuth.gateway.custom) | `object` | no |  | `Custom` only: the annotations this cluster's controller wants, and the keys the template declares it owns. |
| `dialect` | `string` | yes |  | Which router this cluster runs.<br /><br />Values: `"Traefik"`, `"HaproxyIngress"`, `"OpenShiftRoute"`, `"Custom"` |
| `enforcement` | `string` | no | `"Enforce"` | Whether the gate's own verdict is answered or only counted.<br /><br />Values: `"Observe"`, `"Enforce"` |
| `externalUrl` | `string` | yes |  | Where a browser is sent to sign in. |
| `haproxyPrerequisite` | `boolean` | no | `false` | `HaproxyIngress` only: the admin asserts that this cluster's haproxy-ingress controller carries the `config-frontend` prerequisite.<br /><br />**Why this is an assertion and not a check.** That controller builds its auth request by copying the *caller's* headers onto a fixed path, so on a default install the gate is handed no host and no path, a caller can state the `X-Forwarded-Host` it is judged against, and a caller's own `X-Auth-Request-User` reaches the application on any allow the gate does not put a name on. Seven lines in the controller's own ConfigMap close all three — and an annotation cannot, because a per-ingress `config-backend` snippet is emitted *after* the auth call and so rewrites what the application is handed rather than what the gate is asked. The lines therefore belong to whoever installed the controller, which is nobody this operator can write to, own, or pin with `policy-guard`.<br /><br />Nothing can verify it afterwards either: the header a controller sets and the header a caller sends are the same header, with nothing left to compare against. So this is the `Custom` dialect's bargain in a field — enabling the dialect *is* the assertion — and leaving it `false` raises `Degraded` with the reason. The gate still attaches, because a gate a knowing attacker can bypass is better than the endpoint being open to everyone.<br /><br />The seven lines are in `docs/bricks/endpoint-gateway.md`, under *Ground truth*. |
| [`service`](#spec.features.endpointAuth.gateway.service) | `object` | yes |  | The gateway's in-cluster `Service`. |
